词库追加导入、新建词库简化、错题本核心闭环

三项改动，均已通过编译与数据库迁移验证。

一、可以往已有词库加单词了
原来 importPack 只会新建词库，没有「追加到已有词库」的路径，
用户没法给「四级核心词汇」补一个 apple。
- 新增 WordRepository.appendWords(bookId, words)，走 INSERT IGNORE：
  已存在的词连同学习进度原样保留，只统计跳过数量
- wordCount 用 refreshWordCount 重新 COUNT 而非累加，避免并发写算错
- 新增 AddWordsScreen / AddWordsViewModel，词库名只读
- 词库列表每个词库右侧加「+」按钮，内置词库同样开放

二、简化新建词库页
- 删除「从文件导入」整块（文件选择器、importFromFile、queryFileName、
  MAX_FILE_BYTES 及相关 import）
- 文案改为「逐个添加 / 批量粘贴」，说明改成人话
- WordImporter.kt 保留不删，仅切断引用

三、错题本核心闭环
数据库 v2 -> v3：
- word_mark 增加 wrong_reason（自由文本错因）与 wrong_tags（分号分隔标签）
- 新增 MIGRATION_2_3，两列均有默认值，老用户数据不受影响

功能：
- 手动加词入错题本：错题本页「加词」入口 -> 全局搜索页（防抖 300ms）
  原来只能靠答错自动收录，老师划的重点词进不来
- 错因：卡片展开后内联编辑
- 自定义标签：弹窗增删，并列出历史标签供点选
- 筛选：错题本页加「全部 / 薄弱 / 有错因」，搜索框同时匹配错因与标签
- 标记：标为薄弱打标签；已掌握打标签 + 移出错题本

修正一处与需求冲突的既有逻辑：
原代码「答对一次即移出错题本」，但需求是「连续答对自动移出」。
一次答对可能只是蒙对，立刻移出会漏掉其实没记住的词。
改为连续答对 2 次才移出（WRONG_BOOK_GRADUATE_STREAK），答错清零重攒，
界面提示文案同步更新。

顺带修复编码问题：
Routes.kt 与 AppNavHost.kt 本身是非法 UTF-8（早前编码混用留下的乱码，
注释形如「鍏ㄥ眬璺敱琛ㄣ」）。全项目 56 个 Kotlin 文件扫描后仅此两个有问题，
因必须修改，重写为合法 UTF-8 并修复乱码注释，代码逻辑未改动。

- 迁移用真实 SQLite 验证：v2->v3 与 v1->v3 连跳两条路径，
  老数据（笔记、收藏、生词本、学习进度、错题标记）全部保留，
  新列默认为空串，索引完好，新列读写正常
