# P2 数据层说明

本阶段交付 Room 数据库、仓库层、词库导入与内置示例词库。

## 一、数据库表结构

| 表 | 主键 | 说明 |
|---|---|---|
| `word_book` | id (自增) | 词库 |
| `word` | id (自增) | 单词，`(book_id, spelling)` 唯一 |
| `word_progress` | **word_id** | 学习进度，艾宾浩斯调度数据 |
| `study_record` | id (自增) | 逐次作答明细，保留 180 天 |
| `daily_stats` | **date** (yyyy-MM-dd) | 每日汇总，打卡/时长/正确率数据源 |
| `word_mark` | **word_id** | 收藏 / 生词本 / 笔记 |

### 关键设计

**`word_progress` 用 wordId 直接作主键**，不用自增 id。
这样更新进度时 `INSERT OR REPLACE` 一条语句即可，无需"先查再判断插入还是更新"。

**`word_mark` 独立成表**，不并入 `word_progress`。原因：
- 语义不同：进度是算法写的，标记是用户手动的
- 用户可能标记一个还没学过的词，此时不应凭空造出进度记录
- 两个标记都清空后整行删除（`deleteIfEmpty`），避免表膨胀

**`daily_stats` 按天冗余聚合**。统计页如果每次扫 `study_record` 全表，
学习记录积累到几万条后图表会明显卡顿。

**`study_record.study_date` 冗余存日期字符串**。若对该表的 `timestamp`
用 `date()` 函数聚合，会导致索引失效。存成 `yyyy-MM-dd` 字符串可直接走索引。

## 二、索引

```sql
word           (book_id), (book_id, spelling) UNIQUE, (spelling)
word_progress  (next_review_at), (state)
study_record   (word_id), (timestamp), (study_date)
daily_stats    (主键 date)
word_mark      (is_favorite), (is_in_wordbook)
```

`next_review_at` 的索引是必须的——每次进入学习页都要查"到期待复习"，
没有索引会全表扫描。

## 三、词库导入

`WordImporter` 支持两种格式，**按内容自动识别**（首字符是 `{` 或 `[` 走 JSON，否则走 CSV）。

### CSV 格式

```csv
spelling,phonetic,pos,meaning,example,exampleTranslation
abandon,/əˈbændən/,v.,放弃；抛弃,He abandoned his car.,他把车丢弃了。
```

- 表头**可省略**：省略时按 `拼写, 音标, 词性, 释义, 例句, 例句翻译` 顺序解析
- 表头**顺序可任意**，列名大小写不敏感，支持中英文别名（如 `单词`/`word`/`spelling`）
- 只有 `拼写` 和 `释义` 是必需的
- **分隔符自动嗅探**：某几行里制表符多于逗号时改用制表符，因此从 Excel
  直接复制的 TSV 也能导入
- **正确处理引号**：例句里的逗号（`He said, "hello"`）不会导致列错位

### JSON 格式

与内置词库同构，见 `assets/dict/*.json`。也接受纯单词数组 `[{...}, {...}]`。

## 四、内置词库

`assets/dict/` 下 6 个词库，**每个 40 词，共 240 词条**：

| 文件 | 分类 | 词库名 |
|---|---|---|
| `cet4.json` | CET4 | 四级核心词汇 |
| `cet6.json` | CET6 | 六级进阶词汇 |
| `kaoyan.json` | KAOYAN | 考研核心词汇 |
| `gaokao.json` | GAOKAO | 高考基础词汇 |
| `ielts.json` | IELTS | 雅思学术词汇 |
| `toefl.json` | TOEFL | 托福学科词汇 |

> ⚠️ **这是示例包，不是完整词库。**
> 完整的四六级/考研/雅思词表属于商业版权资产（新东方、百词斩等持有），
> 不能随应用分发。每个词的音标、释义、例句均为真实内容，足以跑通全部功能。
> 需要完整词库时，用「导入自定义单词本」导入你自己准备的 CSV/JSON。

### 播种机制

`DictionarySeeder.seedIfNeeded()` 在 `Application.onCreate` 的 IO 协程中调用：

- **幂等**：按 `category` 判断，已存在的词库跳过，重复启动不会重复插入
- **分批**：每 200 条一批插入（SQLite 单语句绑定参数有上限）
- **容错**：某个文件解析失败只记日志，不影响其它词库
- **脏数据过滤**：拼写或释义为空的行直接跳过（否则会占用唯一索引且无法学习）

## 五、仓库层

| 仓库 | 职责 |
|---|---|
| `WordRepository` | 词库 CRUD、搜索、导入、干扰项选取 |
| `StudyRepository` | 学习队列组装、进度读写、收藏/生词本标记 |
| `StatsRepository` | 作答记录、每日汇总累加、连续打卡计算、数据清理 |

**分层原则**：UI 只依赖仓库，不直接接触 DAO。调度算法（P3）只依赖
`StudyRepository`，不碰 DAO。

## 六、与 P3 的接口约定

P3 的 `EbbinghausScheduler` 需要遵守：

```kotlin
// 输入：当前进度（可能为 null，表示新词）+ 本次是否答对
// 输出：更新后的 WordProgress
fun schedule(
    current: WordProgress?,
    isCorrect: Boolean,
    now: Long
): WordProgress
```

`StudyRepository.buildSession()` 已经提供了学习队列的组装逻辑，
复习配额与新词配额是**独立**的——复习积压时用户仍能学到新词。

`androidx.room:room-testing` + 内存数据库做 instrumented test。
