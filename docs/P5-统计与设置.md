## 二、设置存储为什么用 DataStore

设置是「少量键值对 + 高频读 + 低频写」，这正是 DataStore 的设计场景：
无需建表、无迁移负担、天然异步、原生支持 Flow。

**不用 SharedPreferences 的原因**：它在主线程做磁盘 IO 会阻塞，
且没有 Flow 支持，Compose 里还得自己包一层。

持久化的设置项：

| 键 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `theme_mode` | String | SYSTEM | LIGHT / DARK / SYSTEM |
| `dynamic_color` | Boolean | false | Android 12+ 动态取色 |
| `speech_rate` | Float | 1.0 | 语速，限制在 0.5~1.5 |
| `auto_play_audio` | Boolean | false | 进题自动朗读 |
| `repeat_wrong_at_end` | Boolean | true | 答错词本轮重现 |
| `daily_new_limit` | Int | 10 | 每组新词数，5~100 |
| `daily_review_limit` | Int | 20 | 每组复习数，5~200 |
| `last_cache_clear` | String | 从未清理 | 仅用于展示 |

**主题即时生效**：`MainActivity` 直接 collect 这两个 Flow，
用户改设置后整个界面立即重组，无需重启。

**非法值兜底**：读取 `theme_mode` 时用 `runCatching { valueOf(...) }`，
万一存了旧版本遗留的非法值，回退到 SYSTEM 而不是崩溃。

## 三、图表为什么自绘

统计页需要折线图和柱状图。第三方库（MPAndroidChart 等）体积在 1MB 以上，
而这里的需求很简单，用 Compose 的 `Canvas` 自绘更划算：

- **柱状图**：柱高按最大值归一化，最小值限制 2dp 保证 0 值也有可见基线
- **折线图**：先画填充区域（`Path` 闭合到底边）再画折线，视觉层次更清晰
- **单点降级**：只有 1 个数据点时画不出线，改画一个圆点
- **除零保护**：`maxOrNull()?.coerceAtLeast(1)`，全 0 时不会除以 0

## 四、清除缓存的边界（容易误解的地方）

`clearCache()` **只删 cacheDir，不碰数据库和 DataStore**。

这是刻意设计的 —— 「清除缓存」在很多用户心智里等于「清理垃圾」，
如果顺手把学习记录也删了，用户会丢掉几十天的打卡数据。
所以：

| 操作 | 影响范围 |
|---|---|
| 清除缓存 | 只删 TTS 音频缓存、图片缓存 |
| 清空学习记录 | 删进度 + 统计，**保留词库** |

界面上「清空学习记录」用红色文字 + 二次确认对话框，明确写清后果且不可撤销。

## 五、自定义词库导入

### 为什么用 SAF 而不是文件路径

Android 10+ 的分区存储下，文件选择器返回的是 `content://` URI，
**拿不到真实文件路径**。用 `ContentResolver` 流式读取是唯一正确的做法，
而且不需要申请任何存储权限。

### 先预览再导入

流程是「选文件 → 解析 → **预览前 20 条** → 确认导入」。
中间加预览步骤是为了让用户在写库前看到解析结果 ——
否则导入一个格式错误的文件后还得手动去删。

### 文件大小限制

上限 5 MB。超过直接拒绝，避免一次性读入大文件导致 OOM。

### 解析器能力（P2 已实现，此处调用）

- CSV/TXT/JSON 自动识别
- 表头可省略、顺序任意、中英文列名都认
- 分隔符自动嗅探（逗号 vs 制表符）
- 正确处理引号内的逗号

## 六、生词本与收藏

两个视图用 `TabRow` 切换，共用同一套搜索框与列表布局 ——
交互完全一致，只是数据源不同（`observeWordbook()` / `observeFavorites()`）。

- 搜索在内存中过滤（不查库）：生词本通常几十到几百条，
  内存过滤比每次敲键盘都查库更跟手
- 列表项点击展开例句，避免列表过长
- 答错的词由 `StudySessionManager` 自动收进生词本

## 七、设置如何影响学习行为

`StudyViewModel.start()` 会先读设置再组装会话：

```kotlin
val reviewLimit   = settingsRepository.dailyReviewLimit.first()
val newLimit      = settingsRepository.dailyNewLimit.first()
val repeatWrong   = settingsRepository.repeatWrongAtEnd.first()
val autoPlay      = settingsRepository.autoPlayAudio.first()

sessionManager.start(SessionConfig(..., reviewLimit, newLimit, repeatWrong, autoPlay))
```

因此用户改完设置再进学习页，改动**立即生效**，不需要重启应用。
